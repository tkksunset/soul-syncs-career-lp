# Re 自動返信メール導入手順

## 変更内容

Code.gsが修正後のGASコード全文。指定の件名・本文をプレーンテキストで送信し、氏名を先頭に挿入。Netlify Functionsへの応答契約OK / Already registered / Unauthorized / Invalid data / Errorは維持。メール失敗は保存済み受付を取り消さず、Netlifyの再処理でも同じ受付にはメールを再送しない。

変更ファイル：integrations/gas/Code.gs、gas.test.mjs、本手順書。Netlify側・LP・既存の担当者メール通知は変更なし。今回のテストはサービスのモックであり、Google実送信・権限・Webアプリ実行は未確認。

## シートと設定

1. 「キャリア設計申込者管理」のK1に「自動返信状況」、L1に「自動返信日時」を追加。A〜J列と既存データはそのまま。既存のK/L列に別データがある場合は上書きせず、適用前に調整する。
2. L列を日時表示（例yyyy/MM/dd HH:mm:ss）にする。GASとシートのタイムゾーンをAsia/Tokyoに設定。
3. GASのプロジェクト設定 → スクリプトプロパティにAUTO_REPLY_REPLY_TOを追加し、会社の問い合わせ用メールアドレスを設定。WEBHOOK_SECRET・SPREADSHEET_IDは既存値を維持。replyToが未設定/不正な場合は送信せず、未送信（設定不備）を記録。
4. MailAppの送信元はWebアプリ実行ユーザーのGoogleアカウント。replyToは返信先だけを変えるもので、Fromを会社アドレスに偽装する機能ではない。指定Googleアカウントの使用を確認する。

## コード適用・権限承認・再デプロイ

1. 既存GASをバックアップし、Code.gsの全文を反映。他に無関係な関数・トリガーがある場合は保持する。
2. Webアプリの実行ユーザーとなる所有者でGASエディタにログイン。
3. authorizeAutoReplyを選択して実行。MailAppの送信権限を承認する。この関数は送信せず、残り送信枠を照会するだけ。https://www.googleapis.com/auth/script.send_mailが必要。マニフェストでOAuthスコープを明示している場合は既存スコープを維持し、このスコープを追加する。
4. 組織の管理ポリシー等で承認できない場合は、管理者に確認する。実行ログに個人情報・secretを貼らない。
5. デプロイ → デプロイを管理 → 既存Webアプリを編集 → 新バージョンで再デプロイ。同じ/exec URLと既存アクセス設定・実行ユーザーを維持。新URLを作った場合だけNetlifyのGAS_WEB_APP_URL変更とNetlify再デプロイが必要。
6. 同じWebアプリURLならNetlifyのコード・環境変数・メール通知設定の変更は不要。

## 状態の意味と再送

| K列 | L列 | 対応 |
|---|---|---|
| 未送信 | 空 | MailApp未実行。手動再送可 |
| 未送信（設定不備） | 空 | Reply-To等を修正後、手動再送可 |
| 未送信（送信上限） | 空 | Googleの送信枠回復後、手動再送可 |
| 未送信（権限・制限確認） | 空 | 事前の枠照会で失敗。権限等を解決後、手動再送可 |
| 送信処理中 | 空 | 送信開始前に永続化。実行中/タイムアウト/送信後の状態保存失敗の可能性。無条件再送不可 |
| 送信結果不明 | 空 | sendEmail呼び出しで例外。未送信と断定しない。無条件再送不可 |
| 送信済み | 実行日時 | MailAppが例外なく完了し状態保存も成功。受信箱への到達を保証するものではない |
| 既存行の空欄 | 空 | 過去の送信有無が分からないため自動/手動再送しない |

MailAppにはメール送信とシート更新を一つのトランザクションにする仕組みがないため、厳密な「必ず1通届く」は保証できない。送信前状態を保存し、不明時の無条件再送を止めることで二重送信を避ける。

### 既知の未送信行を手動再送

1. A列の対象受付IDを確認し、GASのスクリプトプロパティAUTO_REPLY_RETRY_IDに設定（氏名/メールではなくID）。
2. GASエディタでretryAutoReplyを実行。対象は許可された未送信状態だけ。取得したAUTO_REPLY_RETRY_IDは即座に削除して取り違えを防ぐ。
3. K/L列と受信を確認。再実行・イベント再送でも送信済み行には送らない。

結果不明/送信処理中の場合は、まず実行が終了していること、GAS実行履歴、送信元Googleアカウントの送信記録や管理者のメールログ・対象者の受信状況を確認。未送信を確認できない場合は再送しない。確実に未送信と確認できた場合のみ、運用担当がK列を「未送信」に変更して上記手順を使う。K列を気軽にリセットしない。L列がある行や過去行も同様に調査する。確認した経緯は既存J列等の内部記録に残す。

## 本番テスト

- 管理可能なメールで公開LPから送信。Netlify Formsの保存、担当者通知、シートのA〜J保存を確認。
- 自動返信の件名・氏名・本文・Reply-To、K送信済み/L日時を確認。迷惑メールフォルダも確認。
- 同じ受付IDの再処理で行数と送信通数が増えないことを確認。
- 非本番シート・GASでReply-To未設定による未送信を作り、設定後のretryAutoReplyが1通だけ送ることを確認。
- 不明状態の再送禁止はモックで検証済み。本番で実際の大量送信や上限消費、故意の個人情報送信によるテストは不要。

ローカル：node --test integrations/gas/gas.test.mjs integrations/netlify/*.test.mjs（26件成功）。Googleでの実送信、再承認、実Webアプリの並行動作は本番確認が必要。
